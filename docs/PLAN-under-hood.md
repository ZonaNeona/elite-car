# ELITE CAR — контур «Под капотом» (RAG, агент с инструментами, интеграции на n8n)

## Context
Разбор вакансии ELITE CAR показал: бэклог (бот на 3 роли, дашборд собственника, отделы, прокат/выкуп) закрыт,
но явные требования к кандидату не видны в демо: **эмбеддинги/векторный поиск/RAG, tool calling, интеграции с
учётными системами (1С), дашборд «из нескольких источников»**. Неизвестно, кто будет принимать — PO или инженер.
Решение (идея пользователя): второй контур приложения **«Под капотом»** — отдельный раздел, куда можно перейти и
«поиграть с начинкой»: каждый механизм показан живьём, анимированно (как n8n-холст в iRuler), с двумя уровнями
описания — «простыми словами» и «для инженера». Пользовательский контур меняем минимально.

Сервер: 3.9 ГБ RAM, свободно ~2 ГБ, swap 2 ГБ (занят 1.1 ГБ другими агентами) → **новых тяжёлых сервисов не
ставим**: n8n переиспользуем (lookin-n8n, уже обслуживает iRuler), pgvector — расширение существующего PostgreSQL 16.

## Что получится (для проверяющего)
Кнопка «Под капотом ⚙» в сайдбаре/шапке и на лендинге → отдельный контур с 5 вкладками:
1. **Карта системы** — интерактивная схема: Telegram → вебхук (secret_token, дедуп) → очередь → воркер →
   бизнес-команды (роли, идемпотентность, аудит) → PostgreSQL; LLM-цепочка; n8n-интеграции. Клик по узлу —
   пояснение «просто / для инженера» и ссылка на живой пример.
2. **RAG-песочница** — вопрос → пошагово с анимацией: эмбеддинг запроса → векторный поиск (top-k, косинусная
   близость) + полнотекстовый (tsvector) → слияние RRF → фрагменты с оценками → промпт → ответ со ссылками →
   проверка ссылок; порог «не нашёл — не выдумываю». Рядом — база знаний: документы, чанки, кол-во векторов.
3. **Агент с инструментами** — чат от выбранной роли; трасса: модель выбрала инструмент → аргументы → проверка
   прав роли → результат → финальный ответ; стоимость/латентность/модель каждого шага. Демо-вопросы:
   «сколько я должен?», «какие машины в ремонте дольше недели?», «какие 3 машины самые убыточные и почему?».
4. **Интеграции (n8n)** — 4 воркфлоу на n8n-холсте с анимацией по реальным исполнениям (порт компонента iRuler):
   1С (OData: справочник ТС + начисления), Яндекс Про (выручка водителей), штрафы ГИБДД, телематика (пробег).
   Кнопка «Запустить», история запусков, проигрывание любого исполнения по нодам.
5. **Журнал системы** — живая лента: вебхуки, задачи очереди, вызовы LLM (модель, токены, $, мс, откат на
   запасную модель), вызовы инструментов, синхронизации n8n.

Минимальные изменения пользовательского контура:
- Дашборд: виджет «Источники данных» (1С · Яндекс Про · ГИБДД · телематика — «обновлено N мин назад») +
  карточка «Сверка»: расхождения 1С ↔ наш учёт (пробег, начисления), клик → объект.
- Бот и «Спросить AI»: свободные вопросы идут через агента с инструментами и RAG (вместо текущего classify).

## Реализация

### 1. RAG (pgvector + гибридный поиск)
- Миграция `migrations/versions/005_knowledge_rag.py`: `CREATE EXTENSION vector` (через postgres-суперпользователя
  в deploy-скрипте), таблицы `kb_doc(id, title, url, version, kind)` и `kb_chunk(id, doc_id, n, text,
  tsv tsvector, embedding vector(384))`, индексы HNSW (cosine) и GIN(tsv).
- Корпус (`app/kb/*.md`, ~15–20 документов): существующие `SOURCES` из `app/seed.py` + развёрнутые учебные
  регламенты (выдача/возврат, ДТП, штрафы, выкуп, каникулы, залог, ТО, документы водителя, 152-ФЗ-памятка) +
  шаблон договора. Чанкинг по заголовкам/абзацам ~500 символов с перекрытием.
- Эмбеддинги — **локально**, `fastembed` + `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`
  (384 изм.) — та же модель, что уже работает в RAG agent.shvarev-demo.ru (`/home/hermes/gk-agent/gk_systems/
  embed_worker.py`); кеш модели общий — `FASTEMBED_CACHE_PATH=/tmp/fastembed_cache` (уже скачана, ACL на чтение
  для `elitecar`). Ленивая загрузка в воркере (~150 МБ). Внешних ключей не нужно: прокси OpenRouter жив
  (chat/completions = 200), но маршрут /embeddings в нём не разрешён — и для ПДн локальный расчёт честнее.
  Чужой сервис gk-agent (`:3010`) не используем — демо не связываем между собой.
  Скрипт `scripts/build_kb.py` — пересборка индекса (идемпотентно по хешу текста).
- `app/rag.py`: `search(q, k)` → вектор (cosine) + FTS (`websearch_to_tsquery('russian')`) → RRF → top-k с
  оценками; `answer(q, role)` — ответ через существующую LLM-цепочку `ai.chain()/ai.call()` (`app/ai.py`),
  structured output + проверка, что цитаты ∈ найденным; ниже порога → «в базе нет ответа, передаю сотруднику».
  Возвращает **трассу шагов** (для песочницы).
- Переводим `ai.run()` (mode knowledge/ticket) и бот на `rag.search` вместо подстановки всех `SOURCES`.

### 2. Агент с tool calling
- `app/agent.py`: цикл OpenAI-совместимого tool calling (до 4 шагов) через `ai.client(provider)` — обе модели
  цепочки поддерживают `tools` (проверено). Инструменты — тонкие обёртки над существующей логикой с проверкой
  роли: `get_balance` (`reports.report`), `list_vehicles(status, direction, min_days_in_repair)` (`domain.visible`),
  `vehicle_economics(code|worst=N)` (`reports.report` rows), `find_contract`, `search_knowledge` (RAG),
  `create_ticket` (через `domain.command` — только с подтверждением пользователя: агент возвращает
  «черновик действия», бот показывает кнопку «Подтвердить»). Учёт расхода — существующий `Usage`/дневной бюджет.
- Трасса шагов сохраняется в `Job.result` (`trace: [...]`) → песочница и журнал.
- Бот (`app/telegram.py`): `classify()` → `agent.run(role, text)`; ответ + кнопки действий; фото → заявка как
  сейчас. Веб «Спросить AI» (`AIPanel` в `web/views.tsx`) — режим «Агент» по умолчанию.

### 3. Интеграции на n8n (переиспользуем lookin-n8n)
- Генератор `n8n/build-workflows.mjs` в проекте elite-car (по образцу `T:\JOB\demos\iruler\n8n\build-workflows.mjs`):
  4 воркфлоу `elitecar-1c`, `elitecar-yandex-pro`, `elitecar-fines`, `elitecar-telematics`
  (Schedule + Webhook → HTTP к моку источника → Code-нормализация → HTTP в elite-car `/api/v1/integrations/ingest`
  с HMAC-подписью → ветка ошибки + событие). Импорт/активация CLI в `/var/www/lookin-n8n` (как для iRuler).
- Моки источников в elite-car: `/api/mock/1c/odata/...` (Catalog_ТС, AccumulationRegister_Начисления в формате
  OData), `/api/mock/yandex-pro/...`, `/api/mock/gibdd/...`, `/api/mock/telematics/...` — данные выводятся из
  пространства, с намеренными расхождениями (2–3 машины: пробег/начисление). Наружу закрыть в nginx
  (`location /api/mock/ { return 404; }` — как в iRuler).
- Приём: таблица `source_sync(id, source, started, finished, status, rows, diffs jsonb, execution_id)` +
  `Item(kind="discrepancy")` → карточка «Сверка» на дашборде.
- Чтение исполнений n8n для холста: внутренний вызов уже работающего эндпоинта iRuler
  `http://127.0.0.1:3006/api/execution/{id}` (он читает SQLite этого же n8n: `lib/n8n.ts` → `readExecutionById`)
  — без новых прав на файлы; список исполнений — `/api/executions?workflow=`.
- Фронтенд: порт `components/workflow-canvas.tsx` + `node-meta.tsx` из `T:\JOB\demos\iruler\app` в
  `web/under/` (зависимость `@xyflow/react`), JSON воркфлоу — из `n8n/out/`.

### 4. Контур «Под капотом» (фронтенд)
- `web/under/` : `UnderHood.tsx` (оболочка, вкладки, переключатель «Просто / Для инженера»),
  `SystemMap.tsx`, `RagLab.tsx`, `AgentLab.tsx`, `Integrations.tsx` (n8n-холст), `SystemLog.tsx`.
- API: `GET /api/v1/under/map`, `POST /api/v1/under/rag` (трасса RAG), `POST /api/v1/under/agent` (трасса агента,
  через очередь как `ai`), `GET /api/v1/under/log` (Event/Job/Usage/source_sync), `POST /api/v1/integrations/run`.
- Вход: пункт «Под капотом ⚙» в `web/main.tsx` (сайдбар + шапка), блок на `web/landing.tsx`.
  Стили — токены текущей дизайн-системы (`web/style.css`), обе темы. Анимации — CSS + существующий `motion`
  не тянем; шаги RAG/агента — последовательное «проигрывание» трассы (как replay в iRuler).
- Тексты: каждый блок — «Простыми словами» (1–2 фразы без терминов) и «Для инженера» (термины, параметры, ссылки
  на код/OpenAPI).
